# $SHIT

dedicated token page for `shit-1170.meme-cooking.near` -
`frontend/app/tokens/shit-1170.html`

a special page for one token. unlike the generic token page, this one
lists **every** holder from INTEAR's all-holders api and tags each of
them with a known-holder type. it is reached at
`/app/tokens/shit-1170.html`.

## SUMMARY

the top block shows the token summary: symbol, name, icon, price,
holder count, total supply, decimals, reputation, liquidity, market cap,
and the LP / pool reference.

- **total supply** is `1,000,000,000` SHIT with 18 decimals.
- **price** comes from the intear price api
  (`https://prices.intear.tech/price?token_id=...`), which answers a raw
  number as a plain string. when that call fails, the page falls back to
  INTEAR's `price_usd` from `GET /tokens`.
- **LP / pool reference** is the ref finance pool the token is priced
  against (`REF-5767`). the page reads the pool through the
  `get_pool` view on `v2.ref-finance.near` and derives the pool's
  implied price from the reserves and the paired token's price
  (`wrap.near`). the implied price and the pool TVL are shown next to
  the api price so the two can be compared. when the pool view fails the
  page still renders the summary and says why the LP reference is
  missing.

## HOLDERS

holders come from **INTEAR**, not FastNear. the page calls
`GET /holders` through the middleman (`api_intear_holders_get`) with
cursor pagination and a page size of 100, so the list is the full
holder set rather than a top-100 slice. the response's `total` is
shown next to the filter buttons, and a **LOAD MORE** button appears
while the response still carries a next cursor.

each holder row shows:

| column      | source                                                        |
| ----------- | ------------------------------------------------------------- |
| rank        | position in the loaded list                                   |
| account     | the account id, linked to the account page                    |
| amount      | the raw balance scaled by 18 decimals, with a K/M/B suffix    |
| usd         | the amount times the token price                              |
| % of supply | the balance as a share of the 1,000,000,000 SHIT total supply |
| type        | the known-holder tag                                          |

### % OF SUPPLY

the share of the total supply is computed on `BigInt` — the raw balance
and the raw supply are both 18-decimal integers — and only then scaled
to a percent, so the dust rows below 0.001% still rank correctly. the
display matches the original SHIT info page: two decimals above 0.01%,
three decimals above 0.001%, and `<0.001%` below that.

## TYPE TAGS

every holder is tagged with a known-holder type. the canonical map is
`KNOWN_HOLDERS_ACCOUNTS` from `@huggies/shit-bin`
(`src/const/mainnet/HOLDERS.ts`). that package is not a dependency of
this repo, so the map is kept as a **local copy** in
`frontend/lib/ts/shit_known_holders.ts` — keep it exactly in sync with
the source above.

the types are `dev`, `dex`, `vault`, `nft`, and `burn`. an account that
is not in the map is a `regular` holder.

| type    | icon |
| ------- | ---- |
| `dev`   | 👨‍💻   |
| `dex`   | 🔄   |
| `nft`   | 🖼️   |
| `vault` | 🏦   |
| `burn`  | 🔥   |
| regular | 👤   |

## FILTERS

the filter row offers **ALL** plus one button per type: `DEV`, `DEX`,
`NFT`, `VAULT`, `BURN`, and `HOLDERS` (the regular holders). each type
button carries the same icon as the row tag. filtering happens
client-side over the pages already loaded — it does not refetch.
